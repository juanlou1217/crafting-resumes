# 校招、实习、社招与转行 Playbook

本参考按求职阶段和证据来源选择材料，可与目标岗位 playbook 同时使用。先以用户提供的 JD 和已确认事实为准。

## 使用硬门

下表的关键词、指标、项目和问题都只是追问方向，绝不是候选人事实。不得据此补任职、年限、项目类型、工具、职责、数字或结果。真实性门与单问题门优先于岗位匹配：只有 `confirmed` 事实可进入候选人事实产物；证据不足且影响下一步时，每轮正好问一个最高信息增益问题，不先产出完整简历段落。

**岗位词汇方向（仅用于提问与写作选择）**：课程/作品交付、实习协作、可迁移能力、学习实践、独立实现、采用或展示证据。它们只是问题与表达方向，不是候选人事实；须先确认场景标签、本人动作、责任边界和结果，才能进入 `keyword_evidence_map`。

## 三类证据必须分开

转行及经历较少的候选人必须显式区分以下标签，不得互相升级：

| 标签 | 定义 | 可以支持 | 不能冒充 |
| --- | --- | --- | --- |
| `direct evidence` | 在真实任职、实习或经确认的跨职能工作中，直接完成目标岗位相关任务的证据 | 已确认的目标岗位动作、责任边界和结果 | 未发生的正式岗位、职级、年限或更高贡献 |
| `transferable evidence` | 来自原岗位、校园或其他场景，可迁移到目标岗位的问题解决、用户沟通、分析、协作或交付证据 | 可迁移能力及其原始场景中的真实结果 | 目标岗位的直接任职经验或商业项目经验 |
| `learning/personal project evidence` | 课程、训练、作品集、自学实验或个人项目中的已确认实践 | 学习投入、个人实现、可展示交付和真实边界 | 商业上线、客户采用、公司任职、团队权限或职业年限 |

不能仅凭内容“很像工作”就改变标签。若一段经历同时包含多类证据，拆成不同 claim，分别记录来源、状态、场景和允许的表达。

## 阶段重点

| 阶段 | 优先核实 | 表达边界 |
| --- | --- | --- |
| 校招 | 毕业状态、课程/竞赛/校园/实习的真实场景、本人动作、基础能力、交付与可展示证据 | 课程作业明确写课程项目；社团头衔不自动证明领导力；排名和奖项只用已确认信息 |
| 实习 | 到岗与时长、导师/团队边界、实际任务、交付数量或质量、反馈来源 | 支持或参与不得升级为项目负责人；团队上线不自动归为个人成果 |
| 社招 | 真实任职时间、相关年限、最近经历、职责/决策范围、复杂度、可验证结果 | 总年限不等于相关年限；不得为了 JD 补年限或改写历史岗位名称 |
| 转行 | 转行动机、三类证据清单、目标岗位实践和明显缺口 | 主动说明直接经验缺口；迁移能力和学习项目不得合并成目标岗位任职 |

## AI 转行特别边界

- 调用大模型 API 只能证明已确认的调用与个人实现，不自动证明 AI 产品、算法、Prompt 工程、模型评测或商业落地经验。
- 没有直接证据时，不得补写 Agent、RAG、知识库、用户研究、幻觉治理、成本优化、上线采用或客户反馈。
- 课程、个人工具或 API 实践不得换算为“两年 AI 产品经验”等任职年限；也不得把目标岗位名写成历史岗位。
- 可以如实呈现原岗位的 `transferable evidence` 和个人工具的 `learning/personal project evidence`，同时明确 `direct evidence` 缺口。

## 单问题选择

先问会改变证据标签或贡献边界的一项。对于“教培班主任转 AI 产品，只做过调用大模型 API 的个人工具”，先拒绝虚假年限并标注：班主任事实属于待核实的可迁移证据，个人工具属于学习/个人项目证据，当前没有 AI 产品任职直接证据。随后只问一个问题，例如：“这个个人工具里，你亲自完成且能展示或说明来源的核心功能是什么？”

每轮只能有一个问句和一个问号；收到回答后重新判断三类证据，不用一个问题同时索取工具、用户、难点、指标和结果。
