# 证据、真实性与贡献边界

把表达增强建立在可追溯事实之上。包装只能提高证据密度、顺序和表达精度，不能提高职级、职责、决策权、贡献强度或结果强度。写作应主动使用证据能支持的最高表达，而不是因担心风险退化为模糊流水账；最高表达仍不得超过事实强度。

## 四种证据状态

只使用以下四个状态名；不要自造近义状态：

“候选人事实产物”统一包括简历、ATS 文本、Boss 直聘/猎头/申请邮件、面试故事/追问图、诊断或最终报告，以及 PDF。下表约束这些产物中任何作为候选人事实呈现的内容；非 `confirmed` 项可以在证据台账或报告中被明确标作状态、冲突或缺口，但不能改写成正向候选人陈述。

| `status` | 定义 | 可进入候选人事实产物 |
| --- | --- | --- |
| `confirmed` | 用户明确确认，或由可靠材料直接支持且没有冲突；估算、区间也必须由用户确认 | 是，但仍须通过归因与保密检查 |
| `pending_confirmation` | 有具体线索或候选表达，但来源、口径、时间窗、职责或归因仍待用户确认 | 否 |
| `model_inference` | 模型为理解上下文提出的解释、补全或猜测 | 否；只能用于形成问题，不得写成候选人事实 |
| `conflict` | 两个或以上来源在日期、数字、身份、职责、归因或口径上不一致 | 否；解决前阻断所有受影响内容 |

不得仅因某个来源“看起来更正式”就静默选择冲突的一边。用户确认解决方案后，保留确认来源与口径，再把状态改为 `confirmed`。

## 证据台账固定字段

每条 claim 使用以下固定字段；字段名必须保持不变：

| 字段 | 填写规则 |
| --- | --- |
| `claim` | 最小、可验证的事实陈述；不要把多个独立事实合成一条 |
| `source` | 用户原话、简历位置、证明、作品或其他精确来源；无来源不得确认 |
| `status` | 只能是 `confirmed`、`pending_confirmation`、`model_inference`、`conflict` |
| `time_window` | 事实适用的开始/结束时间或明确未知；日期不得推断 |
| `personal_action` | 候选人本人具体做了什么；未知就明确标记未知 |
| `team_result` | 团队或项目整体结果；不要自动归为个人成果 |
| `attribution` | 个人动作与团队结果之间可证明的归因边界 |
| `metric_definition` | 指标定义、单位、基线、统计范围、时间窗、数据来源及估算属性 |
| `confidentiality` | `public`、`needs_redaction` 或 `restricted`，并记录用户授权；不确定时从严 |
| `allowed_outputs` | 当前 claim 可以进入的产物列表；只有通过归因与保密门的 `confirmed` 才能列入最终公开简历、ATS 文本、Boss/猎头/邮件、面试故事/追问图、报告中的候选人陈述或 PDF。用户明确要求基于其本轮原话起草时，可把原话中的 `confirmed` 最小事实放入当前会话的 `private_review_draft`，但这不等于公开授权。非 `confirmed` 只能列入内部台账、明确标记的缺口/冲突说明和当前唯一问题 |
| `next_question` | 仅在关键缺口或硬门影响下一步时，记录使该 claim 最可能升级、降级或解除冲突的一个问题；无需追问时填 `null` |

字段不得因“信息暂缺”而删除。使用明确的未知值；只有关键未知会影响下一步时，才把其中最高信息增益的一项转成当前轮唯一问题。信息充分且用户已确认时不追问。事实被推翻时，更新台账并使所有引用该 claim 的下游内容失效。

## 绝不推断的事实

公司、岗位、项目、工具、数字和日期均不得推断。也不得从行业惯例、JD 关键词、相邻经历、文件名、上下文暗示或“合理猜测”中补齐它们。

- 公司：不得补全雇主全称、客户名、组织性质或规模。
- 岗位：不得把“实习”“帮忙”补成正式岗位名、职级或负责人身份。
- 项目：不得创造项目名称、范围、业务目标或上线状态。
- 工具：不得因某动作通常使用某工具就声称候选人使用过它。
- 数字：不得编造百分比、金额、人数、性能、排名或精确规模；估算和区间也须用户确认。
- 日期：不得凭证明、简历或推测自动裁决矛盾时间；冲突必须由用户解决。

允许提出不带预设答案的问题；不允许先把猜测写进“优化稿”再请用户确认。真实信息不足时，可以降级为已确认的定性表述，不能添加未确认动作来让句子显得完整。

## 贡献梯级与证据门槛

贡献强度固定为：`支持/协助 < 参与 < 负责 < 推动 < 主导`。选择已确认证据能支持的最高层级，并按 `professional-packaging-and-keywords.md` 检查其他高价值措辞；证据有缺口或冲突时使用较弱层级或阻断，不得因 JD、用户要求“高级”或团队结果而升级。

本节是贡献动词的唯一累计资格门；`professional-packaging-and-keywords.md` 的摘要表不得降低本节累计梯级的任一门槛。包装参考中的检索提示与本节冲突时，一律使用本节更严格的累计门槛。

| 层级 | 逐级最低证据门槛 |
| --- | --- |
| 支持/协助 | 能确认接受了明确任务，并说清本人完成的具体动作；不拥有模块、决策或结果 |
| 参与 | 满足“支持/协助”，且能确认本人持续承担项目中的一部分工作、明确协作边界与交付内容 |
| 负责 | 满足“参与”，且能确认本人拥有一个清晰模块或交付物，对计划、执行和交付负责；仅“做过若干任务”不足以使用 |
| 推动 | 满足“负责”，且能确认本人主动协调关键方、识别并解除具体阻碍、促成事项从停滞到进展或落地；参加会议或跟进不等于推动 |
| 主导 | 满足“推动”，且能确认本人承担主要目标，拥有关键方案/取舍的决策责任、推进节奏和结果责任；团队成果大或本人是主要执行者都不能单独证明主导 |

团队结果必须留在 `team_result`，个人可归因部分写入 `personal_action` 和 `attribution`。如果只能确认“配合导师修改推荐页面”，真实替代应停留在已确认的协助动作；不得补写需求拆解、接口联调、上线验证、推荐系统重构或效果数字。

## 冲突处理

1. 把互相矛盾的原始说法保留在来源中，并将相关 claim 标记为 `conflict`。
2. 找出受影响的简历、ATS 文本、Boss/猎头/邮件、面试故事/追问图、报告和 PDF 内容并阻断相关 claim；不受影响的诚实内容可以继续，但不得把含未解决冲突的整体称为最终版。
3. 冲突会影响下一步时，每轮正好问一个能解决影响范围最大冲突的问题，不同时追问其他缺口。
4. 用户明确裁决并说明可用来源/口径后，更新台账和全部下游版本；不得静默采用简历、证明或任一材料中的日期与数字。

## 保密与公开边界

内部客户信息、客户身份、内部链接、本地绝对路径、未公开经营数据和可反推出客户的组合信息默认不可公开。内部 GMV、收入、成本、转化、名单、合同等经营数据即使数值真实，也不因“能体现成绩”而自动可写。

- 用户要求“给版本”或“优化”只授权在当前任务内生成私下可审阅稿，不等于允许公开投递。没有明确公开/脱敏授权时，不得把 `confidentiality` 推断为 `public`；设为 `restricted` 或 `needs_redaction`。
- `restricted` 或 `needs_redaction` 阻断相关 claim 进入最终公开简历、ATS 文本、Boss/猎头/邮件、面试故事/追问图、正式报告和 PDF。若用户已明确要求起草，可在 `private_review_draft` 中只复述其本轮提供的最小泛化事实，显式标记尚未取得公开授权；不得新增、扩散或称其为最终可投递版，也不得因此机械追问。
- Skill 安装路径、当前工作目录及系统或执行上下文暴露的本地路径不属于用户授权材料；不得据此推断、补全、建议或回显路径。用户明确提供的精确路径只用于必要读取或范围确认，非必要不在响应中重复。
- 优先删除客户身份与绝对经营数据。只有用户确认拥有公开权限或确认脱敏口径后，才可使用不会反推主体的泛化、区间或相对变化。
- 脱敏不能改变事实，也不能自行创造区间或百分比；任何替代口径仍须用户确认。
- 日期冲突与隐私风险同时存在时，两者都阻断受影响内容；先明确将敏感信息排除，再只问一个最高信息增益的冲突问题。

## 造假请求停止规则

用户要求编造、夸大或篡改任一事实时：

1. 明确拒绝具体的贡献升级、假数字或其他虚假要求。
2. 立即停止评分，以及简历、ATS 文本、Boss/猎头/邮件、面试故事/追问图、报告和 PDF 的生成或重写；不得把虚假内容保存为 `pending_confirmation`。
3. 简短说明面试追问、背调、数据口径和职业信誉风险。
4. 给出一个只使用当前 `confirmed` 事实的真实替代；若已确认事实不足以成句，就给表达骨架而不补事实。
5. 可以不提问；若需要恢复正常流程，至多问一个关于可验证真实动作、材料或数据来源的问题。
6. 只有用户撤回造假要求、接受真实边界并提供证据后，才重新进入普通模式。

## 交付前真实性资格门

真实性与隐私是硬性资格门，不参与平均分，也不能被其他高分抵消。出现以下任一项时，受影响 claim 不得进入任何候选人事实产物；造假请求则停止全部候选人事实产物：

- 任一作为候选人事实呈现的 claim 不是 `confirmed`；
- 公司、岗位、项目、工具、数字或日期来自推断；
- 贡献动词高于已确认证据，或团队结果被归为个人成果；
- 影响内容的 `conflict` 未解决；
- 内部客户或经营数据未经公开授权或确认后的脱敏；
- 内容事实快照尚未由用户确认。

失败时只输出阻断原因、明确标记的状态/缺口和当前可安全使用的真实内容。只有关键缺口或硬门会影响下一步时，才正好提出一个最高信息增益问题；信息充分且用户已确认时直接交付，不追问。不得让受影响 claim 进入简历、ATS 文本、Boss/猎头/邮件、面试故事/追问图、报告中的候选人陈述或 PDF。
