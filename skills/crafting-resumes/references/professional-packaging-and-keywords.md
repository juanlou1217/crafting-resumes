# 专业包装与高价值关键词

核心原则：反对事实造假，不反对专业包装。包装改变表达密度、顺序、岗位语言和价值呈现，不改变事实、职责强度、工具、数字或结果。

## 六类允许转换

先拆成事实原子，再选择证据能支持的最高表达。每次转换都要能回指原始 claim。

| 转换 | 最低证据 | 允许行为 | 禁止升级 |
| --- | --- | --- | --- |
| 专业压缩 | 至少一个已确认动作及对象 | 把碎片事实压缩成清晰表达 | 新增动作或结果 |
| 职责澄清 | 已确认本人动作、交付物与责任边界 | 选择证据支持的贡献动词 | 自动升级为负责/主导 |
| 岗位语言翻译 | 原词与岗位词指向同一动作、对象或方法 | 用目标岗位通用术语表达同一事实 | 把相邻经验冒充直接经验 |
| 价值框架 | 已确认触发、交付、采用、机制或可归因变化 | 连接到客户/公司为何投入、交付、质量、效率、稳定性、增长、体验、成本或风险中证据支持的最高一层 | 无证据效果归因；把任一下游事实仅靠改名提升到更高价值层 |
| 结构优化 | 已确认动作、对象、方法、结果中至少一项 | 按相关性组织 action/object/method/result | 改写时间线 |
| 关键词对齐 | 关键词与已确认 claim 直接或语义等价 | 插入与证据语义等价的 JD/岗位词 | 关键词堆砌 |

## 高风险措辞证据门

下表是检索摘要，不是独立最低门槛，也不是替用户生成事实。所有贡献动词最终服从 `evidence-and-truthfulness.md` 的累计贡献梯级；证据不足时必须使用降级表达，即使达门槛也只能描述已确认范围。

| 高价值措辞 | 最低证据 | 证据不足时降级 |
| --- | --- | --- |
| `负责` | 直接承担命名任务或交付物 | `承担`、`参与`、`支持` |
| `推动` | 有推进工作的具体跨人或跨团队动作 | `协调`、`协作`、`跟进` |
| `主导` | 同时具备决策权、协调动作和结果责任 | `负责`、`推动`、`参与` |
| `从 0 到 1` | 新能力且有实质端到端所有权 | `参与搭建`、`负责其中环节` |
| `落地` | 已交付、采用、上线或投入使用 | `完成`、`交付`、`试点` |
| `优化` | 有具体前后变化或明确改善机制 | `改造`、`调整`、`完善` |
| `提升` | 已确认对比、指标定义和个人归因 | 陈述已确认变化，不追加个人因果 |
| `降低` | 已确认对比、指标定义和个人归因 | 陈述已确认变化，不追加个人因果 |

表格中的前三个贡献动词只是检索摘要，最终资格以 `evidence-and-truthfulness.md` 的累计贡献梯级为准：

- `负责` 必须满足“参与”且拥有清晰模块或交付物，并对计划、执行和交付负责。
- `推动` 必须在“负责”基础上主动协调关键方、识别并解除具体阻碍，并实际促成进展或落地。
- `主导` 必须在“推动”基础上承担主要目标，拥有关键方案/取舍的决策责任、推进节奏和结果责任。

“直接承担”须能指出任务或交付物；“推进动作”须说明协调对象及发生的动作；“端到端所有权”须覆盖关键阶段并有决策责任；“采用/上线”须有可核验状态；“前后变化”须有共同口径。“提升/降低”还须区分团队变化与个人归因。未满足时给强而真实的替代，不因拒绝高风险词而停止帮助。

并列确认的动作、采用状态和指标变化，不自动证明时间先后或因果关系。只有来源明确确认该关系时才能连接；否则必须并列陈述，不得擅自用“后”“因此”“带来”“使得”连接，也不得把团队采用或同口径变化归因为个人动作。

## 事实层级不能靠改名跨越

专业包装可以把局部事实放回公司决策与价值系统，但不能只改标题完成升维。按以下通用层级分别取证，停在事实支持的最高层：

| 事实层级 | 直接证明 | 若要上升一层应寻找 |
| --- | --- | --- |
| 组织/客户语境与输入信号 | 问题处于什么背景、哪些人提出或关注 | 公司为何采取行动、真实优先级依据与不做代价 |
| 投入与优先级 | 组织决定分配资源及其当时理由 | 被改变的对象、规模和可检验价值机制 |
| 能力、机制与交付 | 系统或流程具备了什么、是否完成交付 | 实际覆盖、采用、行为变化与机制是否生效 |
| 覆盖、采用与行为 | 谁真正使用、多少流程发生什么变化 | 产品/运营指标的共同口径变化和因果边界 |
| 产品/运营指标 | 可观察的业务过程发生变化 | 公司如何获得收入、保护存量、降低成本或风险 |
| 公司价值 | 经济或战略价值机制已发生 | 可核验的财务/战略结果、时间关系与外部因素 |

可向用户推演的完整公司价值路径可以分别通向新增收入、保护续约/存量收入、销售解锁、采用或漏斗改善、支持/人工成本下降、SLA/合规/声誉风险下降、复用带来的边际经济性或战略选择权。必须把每条路径接回现有线索、具体问题和验证证据，不能只列价值名词。它们在用户确认触发、机制、来源和结果前都是候选逻辑，不能写成候选人事实。候选人可以说明已确认的组织决策背景，不得因自己参与实现就改写为“我决定优先级”。

用户要求无证据高风险措辞时，回复必须同时完成三项：逐项拒绝不能使用的 claim；提供一条只含已确认事实的有竞争力替代；明确说明升级各措辞还需什么证据。至少把 `主导` 对应到决策权、协调动作与结果责任，把 `从 0 到 1` 对应到新能力及端到端所有权，把 `落地` 对应到交付/采用/上线状态，把数字或 `提升/降低` 对应到指标定义、基线/对比、时间窗、来源与个人归因。不能只说“缺少支撑”而省略证据类型。

## 关键词证据映射

每次关键词优化都必须输出完整的六字段 `keyword_evidence_map`。即使当前关键词只能标为 `gap`、`do_not_force` 或 `next_question`，也不得省略任何字段。

| 字段 | 内容 |
| --- | --- |
| `keyword` | JD 原词优先；无 JD 时可用岗位通用词 |
| `source` | 关键词来源及候选证据的精确来源 |
| `candidate_evidence` | 对应的已确认 claim；无证据写“无” |
| `match_strength` | `direct`、`semantic_equivalent`、`adjacent` 或 `none` |
| `allowed_surface` | 可出现的栏目、bullet 或仅风险/提问 |
| `status` | `include`、`deprioritize`、`gap`、`do_not_force` 或 `next_question` |

`direct` 与 `semantic_equivalent` 也必须按职责和结果强度降级；`adjacent` 不得伪装为直接经验；`none` 只能成为 `gap`、`do_not_force` 或必要时的 `next_question`。

## 关键词选择顺序

JD 关键词优先，岗位词库补充，证据映射后插入。禁止关键词堆砌。

同一关键词优先放在证据最强的一处。岗位词库只帮助提问、选材和翻译，不证明候选人拥有相应经历。

## 写作流程

原始事实 → 事实原子 → 岗位价值 → 关键词映射 → 锚点经历选择与排序 → 两个候选表达 → 风险检查 → 用户确认。

两个候选表达可以分别强调交付与岗位相关性，但必须共享同一事实、贡献强度和结果边界。风险检查覆盖高风险动词、数字口径、个人/团队归因、相邻经验冒充、隐私与面试可解释性。

## 简洁示例

### 普通经历的安全包装

已确认“负责三个前端页面，与后端协作修复接口缺陷”时，可写“负责 3 个核心前端页面及交互实现，并与后端协作修复接口相关缺陷”。`负责`、`协作` 和交付对象均有来源；不补工具、上线或效果。

### 拒绝无证据升级但继续给替代

只确认参与需求讨论并完成分配页面时，拒绝“主导从 0 到 1 落地并提升 30%”，可改为“参与需求讨论，按分工完成页面交付”。若要升级，需补决策权、协调动作、采用状态、指标定义和归因证据。

### 无证据 JD 词保留为缺口

JD 要求 Kubernetes，但只确认 React 页面开发时，React 可按证据保留；Kubernetes 标为 `gap` 或 `next_question`，不得写入技能或经历，也不得暗示掌握容器编排。
