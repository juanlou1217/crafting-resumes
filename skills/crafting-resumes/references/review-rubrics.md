# 六维内容审查

审查是材料诊断，不是 ATS 通过率、面试率或录用概率。先运行真实性与隐私资格门，再审查 JD、ATS、HR、面试官、可信度、隐私六维；PDF 技术与视觉验证属于后续独立适配器。

## 先过资格门

当前受审的候选人陈述或对外产物中，只要有未确认事实被写成事实、无证据高价值措辞或贡献升级、伪造数字、未解决冲突进入正文，或未经授权的信息实际泄漏，就标记 `qualification_gate: fail`，列出受影响 claim 与安全动作。台账中被明确隔离、未进入受审产物的 `pending_confirmation`、`model_inference` 或 `conflict` 不使其他诚实内容失败。失败不能被任何高分抵消，不计算综合分，也不能把材料称为可投递最终版。仍按固定六维给出记录，但六维 `score` 全部为 `N/A：资格门失败`；相关维度用 `status: fail`，其他维度用 `status: N/A`，并保留证据、扣分与修复动作。

通过时标记 `qualification_gate: pass`。只有通过后才可计算适用维度的诊断分。不得把门槛本身混入平均分。

## 每维固定记录

六个维度都必须输出以下字段：

| 字段 | 规则 |
| --- | --- |
| `dimension` | 只能是 `JD`、`ATS`、`HR`、`interviewer`、`credibility`、`privacy` |
| `status` | `pass`、`needs_work`、`fail` 或 `N/A` |
| `score` | 按下述五子项公式计算 `0–100` 诊断分；不适用时写 `N/A`，不能写 0 |
| `evidence` | 引用当前材料、JD 原文、事实台账或检查结果 |
| `deductions` | 逐项说明扣分与风险；无扣分写“无” |
| `actions` | 给可执行改进；不得要求编造或泄密 |

每维固定五个子项。每个适用子项满分 20：证据完整且无问题为 20；有轻微、局部且不改变结论的问题为 15；有实质缺口但仍有可用证据为 10；严重错误或适用的核心要求完全未满足为 0。不得给其他子项分值。维度分为 `round(100 * earned_points / applicable_max_points)`；子项因缺少检查所需输入而不适用时写 `N/A`，说明原因并从 `applicable_max_points` 移除，不得当 0。整维无适用输入时状态和分数均为 `N/A`。数值分 `>=85` 为 `pass`、`60–84` 为 `needs_work`、`<60` 为 `fail`。输出五个子项的 20/15/10/0/N/A、证据与扣分，不能凭总体印象猜分。如需综合分，只平均有数值且通过资格门的维度，并展示各维原分与 N/A 项。

## 六维标准

### JD

仅在同时有明确 JD 和候选人证据时适用。五个子项是：

- 高权重硬门是否有直接、真实证据；
- 核心技能词是否自然绑定具体动作，而非只在技能清单出现；
- 主要经历是否对应职责和场景；
- `covered`、`weak`、`gap`、`do_not_force` 是否诚实；
- 目标职级与已确认职责范围是否相符。

每个判断必须引用 JD 原文和候选证据来源。缺 JD 或候选人证据时整维 `N/A`；高权重 gap 必须单列风险，不能被其他覆盖掩盖。

### ATS

五个子项是：标准标题与单栏线性顺序；关键词有事实上下文；技能可识别；时间线完整且目标岗位与历史岗位分离；可解析性及无隐藏词/堆词。未提供实际文件或视觉材料时，第五项中“复杂表格、图片化、文本框、图标、页眉页脚承载关键信息”等视觉检查为 `N/A`，只对可见文本部分评分，不能声称已验证文件解析。

### HR

以 10–20 秒扫读为尺度，五个子项是：目标方向与背景清楚；前部呈现一至两个相关且可防守的锚点证据；主要篇幅服务目标岗位；公司锚点能直观看到真实触发/为什么优先/影响规模/价值机制中证据最强的一项，以及问题、判断/策略和分层结果，个人/团队/组织边界自然；表达简洁且没有任务流水账。证据足以支持却漏掉公司语境、关键判断、交付/采用状态、可核验变化、自然岗位词，或把深度经历埋在常规职责之后，是专业包装不足，应在相应子项扣分并给出修复；不能用更弱、更空泛的文字冒充“更真实”。把任一语境、规模、能力或过程事实直接命名为更高层公司价值也应扣分。缺明确 JD 时，第三项为 `N/A`。不得基于年龄、性别、婚育、籍贯等敏感属性扣分或推断稳定性。

### interviewer

五个子项是：公司锚点的立项触发、为什么现在优先、影响对象/规模和价值获取机制；具体问题定义、当时判断依据、关键机制及真实取舍；关键介入、策略演化、阻力与调整；交付、采用、产品/运营、公司价值各层的结果证据、因果归因与复盘；简历原文、锚点映射、公司级业务案、四层经历地图、证据包和口述细节一致。客观没有公司语境的经历，第一项按真实项目语境检查，不强造商业问题。只复述现象、API、工具或类比不能证明机制深度。职责边界只在影响贡献措辞、归因或真实性时检查，不把“亲自完成了多少”当成经历深度本身。无法回答的锚点或强表述应继续准备、降级或取消前置，而不是用模型补答案。STAR 结构完整不能替代上述深度。

### credibility

五个子项是：事实来源与状态；数字口径和时间窗；个人/团队归因与贡献动词；项目逻辑和时间线；推断、风险与限制披露。公司、正式岗位名、项目名等由动作推断即失败；模板化“高级包装”与无证据效果必须扣分或删除。漏掉证据可支持的高价值措辞属于质量问题；使用证据不能支持的高价值措辞属于资格门失败，二者不得混为同一种保守性偏好。

### privacy

五个子项是：联系方式最小披露；客户/组织身份；内部链接与本地路径；未公开经营数据和组合识别风险；公开授权与脱敏口径。发现未经授权内容时资格门失败；删除或使用经用户确认的脱敏口径。隐私维不是“没有看到风险就满分”：材料范围不全时说明检查边界。

## 四类信号覆盖诊断

用户要求判断项目组合是否完整、材料是否像目标候选人或为何不够有说服力时，在六维审查之外追加不计分诊断。按 `china-recruiting-context.md` 分别列出 `经验`、`经历`、`潜力`、`驱动` 的已确认直接证据、弱证据和缺口。同一 claim 可支持多类信号但不得重复夸大；缺一类不自动失败，也不得依据薪资、公司大小或年限机械推断。

## 锚点与强 claim 面试风险图

锚点 claim 不论是否使用强动词都必须检查；强 claim 包括：`负责/推动/主导`，公司战略、需求触发、优先级、影响规模、价值机制，关键技术或业务判断，取舍/决策，精确数字或效果，商业影响，团队结果，以及任何易被追问的工具深度。先按 `experience-interview.md` 为公司经历建立公司级业务案，再建立四层经历地图，然后为每条锚点或强 claim 检查以下风险边；不要用 STAR 槽位是否齐全代替风险检查。

| layer | `probe_type` | 必问方向 |
| --- | --- | --- |
| `company_context` | `demand_trigger` | 什么客户、市场、数据、运营或风险信号使公司愿意投入；“有反馈/有需求”为什么足以行动 |
| `company_context` | `priority_logic` | 为什么当时先做而不是其他事项，真实比较维度、依赖、不做后果和机会成本是什么；谁作出组织决策 |
| `company_context` | `stakeholder_reach` | 请求者、决策者、实施方、内部角色、客户账户、终端用户和业务量如何区分，实际影响规模在哪一层 |
| `company_context` | `value_capture` | 公司通过收入、续约保护、销售解锁、采用、成本、风险或平台杠杆中的什么机制获得价值，不能由能力范围直接跳结论 |
| `company_context` | `post_delivery_business_evidence` | 交付后在哪一层观察到证据：覆盖/采用、行为、产品/运营指标、公司价值或财务/战略结果 |
| `problem` | `problem_priority` | 真正解决的是什么问题，为什么值得优先处理，不处理的已知后果是什么 |
| `judgment` | `diagnostic_basis` | 当时根据哪些数据、反馈、观察或约束得出判断，而非事后倒推 |
| `judgment` | `alternatives_tradeoff` | 真实考虑过哪些选择，为什么没选，约束和取舍是什么；没有备选时如实记录 |
| `action` | `key_intervention` | 哪个关键介入或机制改变了问题状态，涉及什么流程/数据流/失败边界，为什么它比动作清单更重要 |
| `action` | `resistance_adjustment` | 遇到什么真实阻力、失败或质疑，新信息如何改变策略 |
| `result` | `result_attribution` | 结果如何定义、验证并与本人动作建立边界清楚的联系，外部因素是什么 |
| `result` | `retrospective_counterfactual` | 哪个判断或动作不够好，重来会改变什么及其理由 |
| `cross_layer` | `attribution_boundary` | 只有贡献措辞或结果归因需要时，核实本人、团队和协作方边界 |
| `cross_layer` | `fact_detail_source` | 时间、规模、口径、协作对象、关键节点及可公开证据是否一致且记得住 |

输出一行一个风险边，固定结构为：

| claim（简历原文） | source | layer | probe_type | risk_question | evidence_status | risk | action |
| --- | --- | --- | --- | --- | --- | --- | --- |

只保留对该 claim 适用的风险边；客观不适用但容易被误解的边写一行 `N/A：原因`，不得制造空壳问题。公司锚点至少检查适用的 `demand_trigger`、`priority_logic`、`stakeholder_reach` 与 `value_capture`；声称业务结果时再检查 `post_delivery_business_evidence`。强贡献动词或个人因果措辞才检查 `attribution_boundary`；关键方案或方法至少检查 `diagnostic_basis`、`alternatives_tradeoff` 与 `key_intervention`；数字、效果或商业影响至少检查 `result_attribution`；所有锚点和强 claim 都检查 `fact_detail_source`。不要把公司决策或每条 claim 都机械扩写成“你亲自做了什么”。没有数字或结果但措辞暗示效果时，允许把“未统计/只有交付状态”作为待用户确认的安全答案方向，不能替候选人填写。风险图用于验证一致性，不用于创造面试故事；同一轮需要补证时仍只提出一个最高信息增益问题。
