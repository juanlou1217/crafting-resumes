# 输入模式与状态机

先按固定优先级识别唯一输入模式，再运行该模式有证据支撑的子路径。不得用模型推断补齐缺失输入，也不得为了套完整报告而输出空壳栏目。

## 确定性路由顺序

按以下顺序执行，命中后不再用较低优先级模式覆盖，从而避免“仅 JD / 无现成简历”“仅简历 / 信息严重不足”等重叠：

1. **造假覆盖态**：只要请求包含编造、夸大或篡改事实，立即进入“用户要求造假”。它是最高优先级，覆盖同时存在的简历、JD 或交付请求。
2. **精确授权预检**：若任务依赖文件，读取前先检查是否给出精确文件路径或边界明确的具体目录。授权门未通过时不读取，也不猜测材料属于哪个模式；停在授权门并索要一个具体范围。这是七模式之前的预检，不是第八种模式。
3. **最小读取后分类**：授权通过后，只读取判断输入类型和完成当前任务所必需的已授权内容，再执行以下模式判断；不得根据文件名、未读路径、Skill 安装路径、当前工作目录或其他系统上下文猜测模式。对话中已内联的材料可直接分类，无需文件读取。
4. 已有候选人证据且有明确 JD：一个 JD 进入“简历 + 单 JD”，两个及以上进入“简历 + 多 JD”。候选人证据指对话中已经提供的具体经历事实或简历文本，或最小读取后从精确授权材料中获得的候选人事实。
5. 已有候选人证据但无明确 JD：进入“仅简历/经历”。
6. 有明确 JD 但无候选人证据：进入“仅 JD”。
7. 没有当前候选人证据和明确 JD，但用户明确愿意并能够从真实教育、实习、项目、竞赛、校园、作品或转行经历开始提供事实：进入“无现成简历”。
8. 其余情况进入“信息严重不足”。

岗位名称不等于明确 JD；“我可以之后补充”也不等于已经存在候选人证据。

## 七种输入模式

| 模式 | 判定 | 允许产物 | 阻断条件 | 重新进入条件 |
| --- | --- | --- | --- | --- |
| 用户要求造假 | 请求包含编造、夸大或篡改事实、数字、归因、身份或经历，不论还提供了什么材料 | 真实性拒绝、具体风险、仅基于已确认事实的真实替代；可不提问，若提问至多一个 | 立即停止评分、简历、ATS 版、Boss/猎头/邮件、面试故事/追问图、报告和 PDF；虚假内容不得作为“待确认草稿”保留 | 用户明确撤回造假要求并接受真实边界，且提供可验证事实后，重新判定输入模式 |
| 简历 + 单 JD | 有可解析候选人材料和一个明确 JD | 事实深访、初步证据映射、缺口诊断；事实快照确认后可生成定向简历、ATS 文本、招聘沟通材料、面试准备、报告和可选 PDF | 关键事实未确认、相关冲突未解决、隐私未处理或内容快照未确认时，阻断受影响的候选人事实产物 | 用户确认事实、解决冲突、完成脱敏并确认内容后，从被阻断阶段继续 |
| 简历 + 多 JD | 有可解析候选人材料和两个以上明确 JD | 一份唯一事实底稿、逐 JD 独立映射与诚实版本、版本差异表；通过各阶段门后可分别审查和交付 | 阻断万能混合版；任一版本不得改变事实、数字、日期或贡献强度。普通真实缺口只标记为缺口，仍允许使用已确认事实交付诚实版本；仅当产出必须引入未确认事实或任一资格门失败时，才阻断受影响版本 | 用户确认共同事实底稿和各版本选材；补证后只重算受影响 JD 版本 |
| 仅简历/经历 | 有候选人材料，没有明确 JD | 事实底稿、时间线与可信度检查、基础结构诊断；目标岗位已知时可整理岗位方向草稿 | 无 JD 时阻断 JD 匹配分、关键词覆盖结论和“JD 定制版”；目标方向未知时暂停定向改写 | 用户补充目标岗位可继续方向诊断；补充明确 JD 后进入相应 JD 模式 |
| 仅 JD | 有明确 JD，没有候选人简历或经历证据 | JD 拆解、JD 原文中的硬筛条件、职责与技能优先级、素材采集方向；若候选人证据是当前请求的关键阻断，只提出一个最高信息增益问题 | 阻断候选人匹配分、能力判断以及所有把内容作为候选人事实呈现的产物 | 用户补充具体简历或经历证据后，转入“简历 + 单 JD”或“简历 + 多 JD” |
| 无现成简历 | 没有当前候选人证据和明确 JD，但用户明确愿意且能够从真实教育、实习、项目、竞赛、校园、作品或转行经历开始 | 事实台账、经历结构和条件式逐轮深访 | 关键经历的职责、动作、结果或来源不足且影响下一步时，阻断相应候选人事实产物并正好问一个问题 | 用户回答当前关键问题；证据足以形成可确认事实快照后进入“仅简历/经历”或相应 JD 模式 |
| 信息严重不足 | 不满足以上任一模式 | 简短阻断说明、已知/未知风险，以及正好一个最高信息增益问题 | 阻断候选人匹配结论以及所有把内容作为候选人事实呈现的产物；不得输出看似完整的占位结果 | 用户补充该问题所需事实或具体材料后，按固定优先级重新判定 |

## 无 JD 规则

- 没有明确 JD 时，可以建立事实底稿、检查结构和可信度、澄清目标岗位，并给出通用诊断。
- 不得生成 JD 匹配分、岗位匹配结论、JD 关键词覆盖率或声称“已针对目标 JD 定制”。
- 只有岗位名称而没有具体 JD，仍按无 JD 处理；可以生成不含 JD 分的岗位方向草稿。只有用户要求 JD 级定制且缺少 JD 会阻断该目标时，才索取一个代表性 JD；不生成万能版。
- 没有候选人证据时，即使 JD 完整，也不得推断候选人能力、得分或经历。

## 状态机

```text
检测造假覆盖态；命中则停止禁止产物并给真实替代
  -> 对文件输入执行精确授权预检；对话内联材料跳过文件读取
  -> 最小读取已获精确授权的输入，只到分类与当前任务必要范围
  -> 根据已读取内容按固定优先级识别唯一输入模式；不得根据文件名或未读路径分类
  -> 建立事实台账并标记证据状态
  -> 有 JD 时先解析 JD；有候选人证据时立即做初步证据映射
  -> 检查真实性、冲突、隐私及其他资格门，并识别影响下一步的关键缺口
  -> 若存在关键缺口或未通过的硬门：只问一个最高信息增益问题，更新台账后循环
  -> 若事实足以支持当前请求：不追问，生成当前模式允许的可审阅稿
  -> 若只有普通真实缺口且不阻断诚实产物：标记缺口，不强制追问，继续诚实交付
  -> 用户确认拟交付文字后才标为最终版并进入可选 PDF
```

初步证据映射只用于区分直接证据、弱证据和真实缺口，并选择问题；它不能把 `pending_confirmation` 或 `model_inference` 变成候选人事实。不得把全部 JD 映射推迟到事实快照确认之后。

用户补充或推翻事实时，先更新唯一事实台账，再使所有受影响的映射、评分、草稿和版本失效并重新生成；不得只修正文案表面。

## 硬性资格门

资格门不能被文案质量、JD 相关度、ATS、HR、面试官或视觉得分抵消。这里的“候选人事实产物”统一包括：简历、ATS 文本、Boss 直聘/猎头/申请邮件、面试故事/追问图、诊断或最终报告，以及 PDF。任何状态门都同时约束这些产物中作为候选人事实呈现的内容；未确认项只能在证据台账或报告中以明确的状态/缺口出现，不能写成正向候选人陈述。披露范围另行约束：用户明确要求起草时，当前会话的 `private_review_draft` 可复述其已确认、最小泛化事实并标记 `needs_redaction`；公开简历、招聘沟通、正式报告和 PDF 才要求公开许可或确认后的脱敏。

| 门 | 通过条件 | 未通过时的动作 |
| --- | --- | --- |
| 授权门 | 只读取对话内文本或用户点名的精确文件/目录范围 | 不读取、不扫描；索要具体路径范围 |
| 造假门 | 用户没有要求编造、夸大或篡改候选人事实 | 停止全部候选人事实产物，仅给拒绝、风险与真实替代；至多问一个问题 |
| 事实门 | 候选人事实产物中的职责、动作、结果、来源和归因均为 `confirmed` | 阻断非 `confirmed` claim 在任何候选人事实产物中出现；若该缺口影响下一步，正好问一个最高信息增益问题 |
| 冲突门 | 影响当前产物的数字、日期、身份、职责或归因冲突已解决 | 阻断受影响 claim 进入任何候选人事实产物；不得静默选边。未受影响的诚实内容可继续 |
| JD 门 | 计算匹配分时同时有明确 JD 和候选人证据 | 标记“不适用：缺少 JD”或“不适用：缺少候选人证据” |
| 隐私门 | `private_review_draft` 只使用用户本轮已确认的最小泛化事实并显式标记待确认公开边界；公开产物另须公开许可或确认后的脱敏 | 未获公开许可时仍可生成私审稿，但阻断受影响 claim 进入公开简历、招聘沟通、正式报告和 PDF；不得凭常识把保密状态写成 `public` |
| 内容门 | 用户已确认事实快照和拟交付内容 | 不得称为最终版，不得进入正式招聘沟通、报告或 PDF |
| PDF 门 | 当前模式允许正式交付，且事实、冲突、隐私、内容门全部通过 | 不构建、不导出 PDF |

## 精确路径授权

- 拒绝为了“找素材”自动遍历 workspace、home、知识库、repository 或其他个人文件集合。
- Skill 安装路径、当前工作目录，以及系统或执行上下文中出现的路径，只可用于加载规则或运行环境判断；它们不是用户提供的候选人材料，也不构成读取授权，不得进入用户响应。
- 禁止推断、自动补全、建议或回显用户未显式提供的任何 workspace、home 或本地绝对路径。索要范围时优先不举路径示例；确需说明格式时，只使用中性占位 `/path/to/file.md` 或 `/path/to/project/subdir`。
- 授权必须落到明确的文件路径，或边界清楚的具体目录路径；读取范围不得超出该路径。
- “扫描整个项目”“扫描整个主目录”“你随便找”“不用再问权限”等泛授权不构成精确路径授权。即使用户泛泛授权整个主目录，也必须先索要具体文件或具体目录范围。
- 不得先读取再补问，不得声称已读取未获精确授权的路径。收到用户明确提供的精确范围后仍应最小化读取，只使用与简历任务相关的文件；仅在确认范围确有必要时回显该路径，不要无必要重复本地绝对路径。
- 缺少精确路径时，回复拒绝自动遍历，并只问一个问题，例如：“请提供要读取的具体文件路径，或一个边界明确的子目录路径。”

## 单问题规则

只有在关键缺口或未通过的硬门会影响下一步时，每轮才正好提出一个最高信息增益问题。先完成已有 JD 的解析和初步证据映射，再按以下优先级选题：解除造假门之外的授权硬阻断、解决影响范围最大的冲突、确认关键个人贡献与结果、补足会改变结论的高权重 JD 证据、再改善表达。信息充分且用户已确认时直接交付，不为了“走流程”追问；普通真实 gap 不阻断诚实版本时，只标记缺口。不要一次给问卷，不要用多个问号把多个事实塞进同一题。

造假模式是唯一例外：先停止禁止产物并给真实替代；可以不提问，如需恢复流程则至多提出一个关于可验证真实证据的问题。
