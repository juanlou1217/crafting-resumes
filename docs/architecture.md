# Architecture

## Objective

`crafting-china-resumes` 将中国求职简历制作拆为证据、访谈、岗位语境、写作审查和交付五类职责。主入口只负责路由；较重的规则与岗位知识按当前阶段渐进加载。

## Layers

1. **Router** — `SKILL.md` 定义触发范围、核心真实性门禁、引用路由和最终交付门禁。
2. **Evidence core** — 状态机、证据台账、冲突处理、隐私边界和逐问访谈共同决定哪些信息可以进入输出。
3. **Recruiting context** — 中国招聘流程、JD 映射以及技术、产品、运营、商业、校招和转型岗位打法提供问题方向，不提供候选人事实。
4. **Writing and review** — 写作规则、输出合约与审查量表分别约束 ATS 文本、HR 快速扫描质量、面试叙事一致性和风险问题。
5. **PDF delivery** — 两个确定性 Python 工具只负责准备隔离 Obsidian Vault 和验证导出的 PDF；Obsidian 桌面端是唯一渲染器。

## Data flow

```text
用户材料或 JD
  → 输入模式识别
  → 证据台账与隐私范围
  → 单问题经历访谈（仅在关键信息阻塞时）
  → JD/岗位映射
  → 草稿、审查与面试风险
  → 用户确认事实快照和交付措辞
  → 可投递文本或经验证的原生 Obsidian PDF
```

## Qualification gates

真实性与隐私是资格门禁，而不是可由文笔抵消的评分项。未确认事实、贡献升级、虚构指标、未解决冲突、隐私泄漏和未授权读取任一失败时，相关最终交付必须停止。

## Progressive loading

经历挖掘通常只需要状态机、证据和访谈引用；岗位、JD、写作、审查及 PDF 模块只在对应阶段加载。这使入口保持简短，也避免每次调用消耗全部参考内容。

## Repository boundary

仓库只保存通用 Skill、工具、匿名行为样例和测试。真实简历、联系方式、候选人文件路径、导出 PDF、浏览器状态、本机安装路径与真实验收记录必须保留在仓库之外。

## Verification

- 单元测试验证 PDF 准备器、PDF 验证器、行为资产合约、包结构、第三方许可和确定性树哈希。
- 十二个冻结行为场景覆盖普通项目、过度包装压力、冲突与隐私、JD/简历单边输入、多 JD、转型和多类岗位。
- 候选行为不得相对无 Skill 基线产生资格门禁回归。
